How it works

01

The owner sets the mandate

Fund the account and register each verified payee with the name, the payout wallet and the key that signs their invoices. Caps and the approval line are stored on chain.

02

The agent does the paperwork

It verifies the merchant's EIP-712 signature, runs Confirmation of Payee against the registry, checks caps, deadlines, duplicates and the balance — and explains every step before it spends anything.

03

The contract has the last word

pay() re-runs the same rules on chain. Above the approval line the owner's EIP-712 signature is required, and the mandate tracks the nonce so a co-signature cannot be replayed on a changed amount.

04

Refusals are auditable

A blocked invoice is recorded with recordRefusal(): same invoice id, same reason code, on the same chain. An auditor sees what the agent declined, not only what it paid.

What it stops

  • Invoice fraud. A lookalike invoice with the vendor's name but a new wallet fails Confirmation of Payee.
  • A stolen agent key. It can only call pay() to verified payees inside the caps — it can never withdraw, add a payee or raise a limit.
  • A compromised invoice. The owner's co-signature covers invoice id, payee, amount and deadline, so an edited amount invalidates it.
  • Double payment. Each invoice id settles once, on chain.
  • Runaway spending. Per-payment cap, daily cap and an optional policy expiry.
